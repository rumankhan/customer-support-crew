# Ollama Cloud Configuration Guide

This guide explains how to configure the Multi-Agent Customer Support Crew to use Ollama Cloud instead of OpenAI.

## Quick Setup

### 1. Get Ollama Cloud API Key

1. Visit https://ollama.com/settings/keys
2. Create a new API key
3. Copy the generated key

### 2. Update Your `.env` File

```bash
# Copy the example if you haven't already
cp .env.example .env
```

Edit `.env` and configure:

```env
# ========== LLM Provider Configuration ==========
LLM_PROVIDER=ollama

# ========== Ollama Cloud Configuration ==========
# API key from https://ollama.com/settings/keys
OLLAMA_API_KEY=your-ollama-api-key-here

# Ollama Cloud base URL (default)
OLLAMA_BASE_URL=https://ollama.com/v1

# Model to use (all agents will use this model)
OLLAMA_MODEL=gemma4:31b
```

### 3. Start the Backend

From the **repo root**:

```bash
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8001
```

### 4. Verify Configuration

You should see in the startup logs:

```
Crew initialized:
  Provider: ollama
  Model (low): gemma4:31b
  Model (mid): gemma4:31b
  Ollama Base URL: https://ollama.com/v1
```

## Configuration Options

### Ollama Cloud (Recommended)

**Production-ready managed hosting:**

```env
LLM_PROVIDER=ollama
OLLAMA_API_KEY=your-api-key
OLLAMA_BASE_URL=https://ollama.com/v1
OLLAMA_MODEL=gemma4:31b
```

**Advantages:**
- No local installation required
- Scalable and managed by Ollama
- Accessible from anywhere
- Pay-as-you-go pricing
- Available models: gemma4:31b, llama3.1:8b, llama3.1:70b, and more

### Local Ollama (Development)

For local development, you can run Ollama locally (requires additional configuration):

1. **Install Ollama:** Download from https://ollama.ai
2. **Pull model:** `ollama pull gemma4:31b`
3. **Verify:** `ollama run gemma4:31b "Hello"`
4. **Configure as OpenAI-compatible endpoint:**

```env
LLM_PROVIDER=openai
OPENAI_API_KEY=fake-key  # Ollama doesn't check this
OPENAI_BASE_URL=http://localhost:11434/v1
OPENAI_MODEL_LOW=gemma4:31b
OPENAI_MODEL_MID=gemma4:31b
```

**Note:** Local Ollama requires using OpenAI-compatible mode.

## How It Works

The crew uses dynamic LLM provider selection:

1. **Provider Detection:** Checks `LLM_PROVIDER` environment variable
2. **Model Selection:** 
   - Ollama: Uses `OLLAMA_MODEL` for all agents
   - OpenAI: Uses tiered models (gpt-4o-mini for low tier, gpt-4o for mid tier)
3. **LLM Initialization:**
   - Ollama: Uses LiteLLM's OpenAI-compatible route
     ```python
     LLM(
         model="openai/gemma4:31b",
         api_key=os.getenv("OLLAMA_API_KEY"),
         base_url="https://ollama.com/v1"
     )
     ```
   - OpenAI: Standard OpenAI configuration
     ```python
     LLM(model="gpt-4o-mini")
     ```
4. **Agent Assignment:** All 4 agents use the configured LLM provider

## Supported Models

### Recommended Models

| Model | Size | Use Case | Speed | Quality |
|-------|------|----------|-------|---------|
| `gemma4:31b` | 31B | Production | Medium | High |
| `llama3.1:8b` | 8B | Development/Testing | Fast | Good |

- **gemma4:31b** (Default): Best balance of speed and quality for customer support
- **llama3.1:8b**: Faster, lower cost, good for development
- **llama3.1:70b**: Best quality, but slower and more expensive

## Troubleshooting

### Authentication Issues

**Problem:** `OLLAMA_API_KEY required when LLM_PROVIDER=ollama`

**Solutions:**
1. Create API key at https://ollama.com/settings/keys
2. Add key to `.env` file: `OLLAMA_API_KEY=your-key-here`
3. Restart the backend

### Connection Issues

**Problem:** Cannot connect to Ollama Cloud

```
Error: Failed to connect to Ollama at https://ollama.com/v1
```

**Solutions:**
1. Verify API key is valid (check https://ollama.com/settings/keys)
2. Check internet connection
3. Verify `OLLAMA_BASE_URL=https://ollama.com/v1`
4. Check Ollama Cloud status at https://status.ollama.com

### Model Not Available

**Problem:** Model not found or not available

```
Error: Model 'gemma4:31b' not found
```

**Solutions:**
1. Verify model name is correct
2. Check available models at https://ollama.com/library
3. Try a different model like `llama3.1:8b`

### Slow Responses

**Problem:** Crew taking too long to respond

**Solutions:**
1. Switch to a smaller model (e.g., `llama3.1:8b`)
2. Reduce `MAX_ITER` in `.env` (default: 12)
3. Check network latency to Ollama Cloud
4. Consider upgrading to OpenAI for faster responses

## Cost Optimization

### Ollama Cloud Pricing

Pricing is based on:
- **Input tokens:** Tokens sent to the model
- **Output tokens:** Tokens generated by the model

### Tips to Reduce Costs

1. **Use smaller models:** `llama3.1:8b` is cheaper than `gemma4:31b`
2. **Reduce iterations:** Lower `MAX_ITER` in `.env`
3. **Optimize prompts:** Shorter, clearer prompts use fewer tokens
4. **Cache responses:** Consider caching common queries
5. **Rate limiting:** Set appropriate `MAX_RPM` (requests per minute)

## Migration from OpenAI

To migrate from OpenAI to Ollama Cloud:

1. **Backup `.env`:**
   ```bash
   cp .env .env.backup
   ```

2. **Update configuration:**
   ```env
   # Comment out OpenAI settings
   # OPENAI_API_KEY=sk-...
   # OPENAI_MODEL_LOW=gpt-4o-mini
   # OPENAI_MODEL_MID=gpt-4o

   # Add Ollama settings
   LLM_PROVIDER=ollama
   OLLAMA_API_KEY=your-ollama-api-key
   OLLAMA_BASE_URL=https://ollama.com/v1
   OLLAMA_MODEL=gemma4:31b
   ```

3. **Restart backend** (repo root):
   ```bash
   python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8001
   ```

4. **Test thoroughly:** Verify all agent responses meet quality standards

## Technical Implementation Details

This configuration uses a centralized LLM configuration pattern with:
- **LiteLLM OpenAI-compatible route** - Uses `openai/` prefix for Ollama models
- **API key authentication** - Required for Ollama Cloud security
- **Default base URL** - `https://ollama.com/v1` for Ollama Cloud
- **Centralized configuration** - Single source of truth in `backend/llm_config.py`
- **Shared LLM instance** - All agents use the same configured LLM
